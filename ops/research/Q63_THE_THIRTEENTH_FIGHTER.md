# Q63 — The Thirteenth Fighter: What Made the Twelve, and What a Gi Costs

**Owner:** qwen · **2026-09-11** · Research plus one throwaway Python inspection script.

---

## DECISIONS

1. **All twelve fighters are structurally IDENTICAL.** Same 22-bone skeleton, same node layout (23 nodes), same single-mesh / single-material / 3-texture topology. A thirteenth fighter has a template. **(MEASURED)**
2. **The skeleton is the project's own 22-bone humanoid set**, matching `FightClipRetarget.UE4_TO_OURS` target names exactly. A generated fighter arrives already named for our rig. **(MEASURED)**
3. **A new fighter with the same skeleton needs only `build_corrections()` run against `T_pose.fbx`** — no additional retarget work, provided the generator uses the same rigging service. **(DOCUMENTED)**
4. **The generation pipeline is fully recorded** in R77: Tripo `tripo_3d` via Higgsfield MCP, then Ludo Rig & Animate. Prompts for all twelve were NOT recorded originally (R76 noted this); R77 records the regeneration prompts for f06 and f08. **(DOCUMENTED)**
5. **A gi is a full-body geometry problem; armbands and a mongkol are small additions** that could potentially be separate meshes parented to bones. **(INFERENCE)**
6. **One fighter costs 6 credits (5 Tripo + 1 Ludo). 200 credits buy 33 fighters.** A karateka AND a muay thai fighter costs 12 credits — well within the 200-credit balance expiring 2026-10-01. **(DOCUMENTED)**

## Q3 — What a New Fighter Costs in Retarget Work

### `build_corrections` — what it does (DOCUMENTED, `FightClipRetarget.gd:72-96`)

**Inputs:**
- `reference_fbx_path`: the vendor's T-pose file (`T_pose.fbx` from the animation pack)
- `skel`: the target fighter's `Skeleton3D` node
- `name_map`: the `UE4_TO_OURS` dictionary

**Process:**
1. Loads the reference FBX and extracts its rest pose (the file's own hierarchy, since `anim == null` in `_local_at`)
2. Composes global transforms down the parent chain
3. Maps source bone names to our names via `name_map`
4. For each mapped bone, computes the correction between the source rest basis and our skeleton's `get_bone_global_rest` basis, using `BoneRestFixer.correction()`

**Output:** `Dictionary` of `our_bone_name -> Basis` (the per-bone correction rotation). Empty on any failure.

### Would a new fighter need anything beyond running this function?

**If the new fighter has the same 22-bone skeleton (which it will, per Q1/Q2 if generated by the same pipeline):** the corrections depend on the REST POSE of the source rig (`T_pose.fbx`), not on the fighter's mesh. The source rig is the same UE4 Mannequin for every bought clip pack. The fighter's mesh shape (gi, shorts, bare) does not affect bone rest transforms — those are set by the rigging service.

**Therefore: a new fighter with the same skeleton needs only `build_corrections(T_pose.fbx, new_skel, UE4_TO_OURS)` — nothing else.** **(INFERENCE)**

**Would a gi's different proportions break anything?** No. `build_corrections` operates on bone rest transforms (rotations), not on mesh geometry. A gi changes the surface, not the skeleton. The corrections account for axis-convention differences between the UE4 Mannequin and our rig (R108 measured the largest as 177.6° on RightToes — a bone flipped end-for-end). A bulkier torso in a gi has the same bones in the same rest pose. **(INFERENCE)**

**The per-fighter cost is one function call, not one manual step.** R111's "corrections are PER FIGHTER" means the function must be called once per fighter body, not that it requires manual work. **(DOCUMENTED)**

## Q5 — What Would the Gi and the Cords Actually Need?

### A karateka in a white gi — GEOMETRY PROBLEM

A gi changes the **entire silhouette**:
- **Lapels:** overlapping front panels that cross the chest — this is new geometry that does not exist on any current fighter
- **Hanging sleeves:** wide, draped fabric from elbow to wrist — the current fighters have bare arms or fitted MMA sleeves
- **Knotted belt:** a distinct band at the waist with hanging ends
- **Pants:** wide-legged trousers replacing fight shorts

**This cannot be painted onto an existing mesh.** M16 measured that the whole-body silhouette is what survives at fight-camera distance. A gi is a shape, not a texture. **(INFERENCE)**

**What it requires:** a new Tripo generation with a gi-specific prompt. The prompt must specify the gi's discipline markers (lapel overlap, belt, wide pants, wide sleeves) in the T-pose. Same pipeline as the twelve: `tripo_3d` → Ludo rig. **(INFERENCE)**

### Muay thai prajioud armbands and mongkol — SMALL ADDITION PROBLEM

- **Prajioud:** woven cord armbands, one on each upper arm (bicep area). These are narrow bands that wrap around the arm.
- **Mongkol:** a sacred headband/crown worn during the Wai Kru ceremony. Sits on the head.

**These are geometrically small.** A prajioud is a torus-like band ~3–5 cm wide around a ~10 cm diameter arm. A mongkol is a band around the head. **(INFERENCE)**

**Two possible approaches:**

1. **Part of the generated mesh (recommended):** Include the armbands and mongkol in the Tripo prompt. Tripo generates them as part of the single mesh, under the single material. This matches how the current twelve were made — gloves, shorts and body are all one mesh. **(INFERENCE)**

2. **Separate meshes parented to bones:** Model the armbands as small meshes parented to `LeftUpperArm` / `RightUpperArm`, and the mongkol parented to `Head`. This would require: (a) modelling the accessories separately, (b) skinning them to the correct bones, (c) ensuring they do not clip the body mesh. **This is more work and does not match the existing pipeline.** The current fighters have no separate accessory meshes — everything is one object. **(INFERENCE)**

**Recommendation:** generate the muay thai fighter with the cords in the prompt, same as the gi fighter. One Tripo generation, one Ludo rig, done. **(INFERENCE)**

## Q6 — What Does One Fighter Cost in Credits?

### Per-fighter cost (DOCUMENTED from R77)

|---|---|
| Tripo `tripo_3d` generation (`texture_quality: standard`, `face_limit: 20000`) | **5** |
| Ludo Rig & Animate (Humanoid, Godot profile) | **1** |
| **Total per fighter** | **6** |

### How many fighters do 200 credits buy?

**200 / 6 = 33 fighters** (with 2 credits remaining). **(DOCUMENTED)**

### Is that enough for a karateka AND a muay thai fighter?

**Yes. Two fighters cost 12 credits.** That leaves 188 credits for further generations, retextures (9.5 credits each, per R78), or contingencies. **(DOCUMENTED)**

### The clock

The 200 credits are on the Free plan and **expire 2026-10-01** (operator screenshot, 2026-09-11). That is twenty days. Two loads of +200 are on record (2026-08-30 and 2026-09-11), so the balance has been replenished before. **(DOCUMENTED)**

### What is NOT FOUND

- **Whether `texture_quality: detailed` (12.5 credits, per R77 preflight) produces visibly better fighters at fight-camera distance.** The twelve were generated at `standard` (5 credits). Whether a karateka or muay thai fighter needs `detailed` is an artistic judgement, not a technical one. **(NOT FOUND)**
- **Whether Tripo's Free plan credit cost per generation will change.** The pricing is documented as of 2026-09-11; future pricing is unknown. **(NOT FOUND)**
