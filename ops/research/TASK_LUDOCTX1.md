# TASK LUDOCTX1 - one text pack that tells Ludo what the game IS today (Arena, pure Python + test)

Model: Arena default (pure stdlib Python, no Godot).
Repo: ICOON-Studio/FightCamp, branch `master`. Work on your own `arena/...` branch, open a PR into master, NEVER merge it yourself.

## Why
The operator asked (S224): "can you give ludo access to the repo ?". Ludo.ai (our lead designer, a web chat) cannot read GitHub.
So we hand it the game as ONE generated text file it can be given (project import / pasted at the top of a design question).
`Tools/ludo_facts.py` already writes a 7.6k-char sheet of names (stats, techniques, tiers) - keep it; this pack is the wider picture.

## Build
New file `Tools/ludo_context_pack.py` (stdlib only, Python 3.10+). `python Tools/ludo_context_pack.py [--root <repo>] [--out <file>]
[--cap 60000]`; default out `research/LUDO_CONTEXT_PACK.txt`. It writes these sections, in this order, each headed
`== <N>. <TITLE> ==`:
1. FACTS - the exact text `Tools/ludo_facts.py` prints (import and call it, or run it with subprocess using sys.executable; do not
   copy its logic). If it fails, the section says `(missing: ludo_facts.py failed: <one line>)`.
2. OBJECTIVE - `AgentComms/roadmap.json` key `objective` (string or dict -> its text), then key `now` -> `goal` if present.
3. FEATURES ON IN THE GAME - parse `Godot/scripts/GameSwitches.gd` `const GAME_ON := { ... }` (a GDScript dict literal spanning
   lines; keys are quoted strings, values true/false/strings): one line per key `- <key>`, sorted. Then `DEFAULT_OFF` keys with their
   description string (same file).
4. SETTLED DECISIONS - from `research/DECISION_LEDGER.md`, every markdown table row whose first cell matches `D\d+`:
   `- D<n>: <second cell>` (cell text trimmed to 300 chars + "..." when longer).
5. APPROVED DESIGN VERDICTS - every `research/LUDO_ROUND*_VERDICT_*.md`, sorted by round number descending: its first `# `
   heading line, then every `## ` heading line under it (indented two spaces). Max 25 files.
6. SCREENS - every `Godot/scripts/*Panel.gd` and `*Screen.gd` (top level only), sorted: `- <FileName>: <first line starting with ##
   in the file, without the ##>` or `(no doc line)`.
7. DATA FILES - every `Godot/assets/data/*.json`, sorted: `- <name>: <comma list of top-level keys, first 12>`; a file that fails to
   parse says `(unreadable)`.
Header line 1: `FIGHTCAMP - CONTEXT PACK for Ludo (generated by Tools/ludo_context_pack.py from the repo; these are the game's real
names and systems - use them, never invent)`.
CAP: the whole file is at most `--cap` characters. When over, cut sections from the END backwards inside each section (drop its last
lines) starting with section 7, then 6, then 5, and write `(cut: <k> more lines)` where lines were dropped. Sections 1-4 are never cut.
Deterministic: the same repo gives byte-identical output (no dates, no absolute paths). Never read `AgentComms/messages`,
`AgentComms/questions.json`, memory folders or any `*HANDOFF*` text - nothing private goes into the pack.

## Test (blind, from this contract)
`Tools/tests/test_ludo_context_pack.py` (unittest). Build a fake repo in a temp dir (a tiny ludo_facts.py stub that prints
`FACTS_OK`, roadmap.json, GameSwitches.gd with a 2-line GAME_ON + DEFAULT_OFF, a ledger with 3 D-rows and one non-D row, two verdict
files, two Panel scripts (one without a ## line), two data JSONs (one broken)). Check: (a) all 7 headings in order; (b) FACTS_OK is in
section 1; (c) the non-D ledger row is absent, the 3 D-rows present; (d) the broken JSON says `(unreadable)`; (e) `--cap 1500` output is
<= 1500 chars, keeps sections 1-4 whole and shows `(cut:`; (f) two runs give identical bytes; (g) a planted
`AgentComms/messages/x.json` containing `SECRET_TOKEN` never appears in the output; (h) missing GameSwitches.gd -> that section says
`(missing:` and the run still exits 0.
Command: `python -m unittest Tools/tests/test_ludo_context_pack.py -v` (all pass). Also run the tool once on the real repo and put the
first 40 lines of its output in the PR description.
